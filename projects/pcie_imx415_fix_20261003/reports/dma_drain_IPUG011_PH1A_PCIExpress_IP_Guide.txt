上海安路信息科技有限公司SALPHOENIX®1A（以下简称PH1A）系列FPGA，内嵌了PCI Express（以
下简写为PCIe）硬核。该硬核的详细说明，请见《UG913_安路科技PH1A 系列FPGA PCIE 用户手册》。
本手册主要介绍如何通过TD 软件IP Generator 中的PCI Express IP 图形化界面来配置、例化和使用
PCI Express 硬核。

1.1 功能描述 
本IP 支持以下用户可配置选项： 
 
支持PCI Express Endpoint、Legacy PCI Express Endpoint，Root Port of PCI Express Root 
Complex 
 
PH1A 系列FPGA 支持Gen1/Gen2/Gen3 link speed，支持X1/X2/X4 link width 
 
支持简易和高级配置模式 
 
支持1~2 个Physical Function，每个Physical Function 支持0~2 个Virtual Function 
 
支持PME 和ASPM 
 
支持Legacy INT/MSI/MSI-X 
 
支持多个能力寄存器 
- FLR (Function Level Reset) 
- AER (Advanced Error Reporting) 
- Device SN (Serial Number) 
- ARI (Alternative Routing ID Interpretation) 
- SR-IOV (Single Root I/O Virtualization)

1.2 资源 
PH1A 系列FPGA PCIe IP 会根据客户定制时的不同选择，消耗少量的可编程资源，包括一个PLL。
消耗的可编程资源，主要用于PCIe 控制器的初始化，以及对PCIe 输出时钟，Clock Skew 的平衡。

2 IP 说明 
2.1 界面说明 
本IP 一共有7 个页面用于配置PCI Express 硬核的参数。分别是“PCIe Basic”、“Capability 
1” 、“Capability 2” 、“ID and Class” 、“BAR”、“Port Control”和“Summary”，分别是PCIe 的
基本设置、Capability 寄存器设置1、Capability 寄存器设置2、Vendor ID/Device ID/Class Code
设置、BAR 设置、端口控制和总结页面。以下小节将分别介绍各个页面的选项的含义和使用方法。 
2.1.1 第一页PCIe Basic 
 
图 2-1 IP GUI 第一页PCIe Basic 图示  
上图显示 IP 图形界面第一页“PCIe Basic”的默认设置选项。 
Device Type 
Device Type 默认选项为PCI Express Endpoint，用户可选PCI Express Endpoint，Legacy PCI 
Express Endpoint，Root Port of PCI Express Root Complex。当用户需要支持IO 空间、作为Completer
响应Lock Memory 访问时，请选择Legacy PCI Express Endpoint；否则，请选择PCI Express Endpoint。
当用户需要FPGA 作为RC 端时，请选择Root Port of PCI Express Root Complex。 
PCIe Generation 
对于PH1A 系列，PCIe Generation 默认选项为Gen1，用户可选Gen1/Gen2/Gen3。 
Link Width 
Link Width 默认选项为X1，用户可选为X1/X2/X4。用户配置为X1、X2 或X4，生成的.v 文件端口
上，用户分别看到1、2 或4 对差分对。硬核默认支持Lane Reversal，无须特别设置。

Link Location 
对于PH1A400 以及PH1A90，无论封装，PCIe IP 根据不同位宽，选择SERDES BANK 的位置，x1 时
为BANK83 Lane1,x2 时为BANK83 Lane0 和Lane1，x4 时为BANK82 和BANK83 所有lane。 
对于PH1A180，无论封装，PCIe IP 根据不同位宽，选择SERDES BANK 的位置，x1 时为BANK81 
Lane1,x2 时为BANK81 Lane0 和Lane1，x4 时为BANK81 和BANK80 所有lane。 
Reference Clock Frequency 
当前PCIe IP 物理层差分参考时钟输入频率默认为100Mhz。 
对于PH1A400，无论封装，Link Width 为X1/X2 时，默认使用BANK83 的差分参考时钟作为输入源；
Link Width 为X4 时，默认使用BANK82 的差分参考时钟作为输入源。 
对于PH1A90，无论封装，Link Width 为X1/X2 时，默认使用BANK83 的差分参考时钟作为输入源；
Link Width 为X4 时，默认使用BANK82 的差分参考时钟作为输入源，也可选BANK83。 
对于PH1A180，无论封装，Link Width 为X1/X2 时，默认使用BANK81 的差分参考时钟作为输入源；
Link Width 为X4 时，默认使用BANK80 的差分参考时钟作为输入源，也可选BANK81。 
PCIe Application Mode 
PCIe Application Mode 默认为Basic，用户可选为Basic 或Advanced。Base 为简易配置模式，用
户不需要设置PCI Express 的Capability 寄存器。 
PCIe Application Mode 只有被设置为Advanced 时，用户才能设置第二页Capability 1 和第三页
Capability 2。 
PCIe AUX Clock Frequency 
设置PCIe 辅助时钟频率，可选25Mhz、50Mhz 和100Mhz。辅助时钟用于上电初始化PCIe IP 配置。 
Include Pipeline Logic 
设置PCIe IP 是否包含时序打拍优化逻辑，默认使能，建议用户使能该选项，有助于PCIe IP 时序
收敛。 
Export DAT File 
PCIe IP 配置信息生成与IP 同名的.dat 文件，.dat 信息可以存储到rom 中，用做PCIe 自恢复。
在使能Include Pipeline Logic 后,该选项强制使能。

Physical Functions 
1. Physical Function 0 
Physical Function 0 默认勾选。 
PF0 MAX Payload Size 默认是2048 Bytes，用户可选为128/256/512/1024/2048 Bytes。 
Extended Tag Field 默认勾选，用户可以选择不勾选。Extended Tag Filed 将应用于所有的
Physical Function 和Virtual Function。 
2. Physical Function 1(EP Only) 
Physical Function 1 默认是不勾选，用户可以选择不勾选。当用户使能Physical Function 1 时，
用户将会得到2 个Physical Function，这个PCIe Device 就变成了多功能设备。 
PF1 MAX Payload Size 默认是2048 Bytes，用户可选为128/256/512/1024/2048 Bytes。 
Virtual Functions(EP Only) 
1. PF0-VFs 
想要使用PF0 的VF，请先使能SR-IOV，然后选择Number of VFs。Number of VFs 可选为1/2。 
用户可以设置VFs Device ID，这个ID 将作用于PF0 的所有VF。 
2. PF1-VFs 
只有Physical Function 1 被使能时，PF1_VFs 才可以被用户设置。 
想要使用PF1 的VF，请先使能SR-IOV，然后选择Number of VFs。Number of VFs 可选为0/1/2。 
用户可以设置VFs Device ID，这个ID 将作用于PF1 的所有VF。 
Power Management 
1. PM CAP Reg 
PM Capability 中，D1 support 默认被勾选，D2 support 默认不勾选，两者都允许用户选择不勾
选。 
2. PME Support(EP Only) 
PM Capability 中，D0/D1/D2/D3hot 的PME 默认不勾选，都允许用户选择不勾选。另外，D3cold 的
PME 是使能的，但没有在IP GUI 上呈现出来。 
当用户想分别使能D1、D2 时，请先在PM CAP reg 里分别使能D1 support、D2 support。 
3. ASPM Support 
PCIe 本地电源管理机制，默认是No ASPM。No ASPM/L0s/L1/L0s and L1，允许用户四选一。

Interrupt(EP only) 
Interrupt 下面有4 个子页，分别是PF0、PF1、PF0-VFs 和PF1-VFs。PF0 是Physical Function 0
的简称，同样的，PF1 是Physical Function 1 的简称，PF0-VFs 和PF1-VFs 分别是PF0 和PF1 所有的
Virtual Function 的简称。 
1. PF0 和PF1 
对PF0 和PF1，用户的可设置分为INT Pin、MSI 和MSI-X。 
(1) INT Pin 
INT Pin 兼容了PCI 的中断机制。 
当只有PF0 被使能时，PF0 的INT pin 为用户可配置为None 或INTA，默认为None。 
当PF0 和PF1 都被使能时，PF0 和PF1 的INT 默认都为None，可选为None 、INTA、INTB、INTC 和
INTD。 
(2) MSI 
PF0 的MSI 默认为不使能，可选为使能或不使能。

当PF1 被使能时，PF1 的MSI 默认为不使能，可选为使能或不使能。当PF1 不被使能时，PF1 的MSI
不可设置。 
Vector 默认是4，用户可选为1/2/4/8/16/32。此值指示了软件可配的连续中断的个数。 
64 bit address 默认不被使能，用户可选为使能或不使能。 
Per-Vector Masking 默认使能，不可设置。 
(3) MSI-X 
PF0 的MSI-X 默认为不勾选，可设为不勾选。 
当PF1 被使能时，PF1 的MSI-X 默认为不勾选，可设为勾选。当PF1 不被使能时，PF1 的MSI-X 不

2. PF0-VFs 和PF1-VFs 
PF0-VFs 和PF1-VFs 的MSI-X Table 和PBA 的设置，请参考PF0 和PF1 的MSI-X。 
Extended Capability 
以下扩展能力寄存器，分别针对Physical Function 0 和Physical Function 1 进行设置。 
当Physical Function 1 没有被使能时，PF1 的扩展能力寄存器无法被用户设置。 
1. AER Capability 
AER Capability 默认被使能，不可设置。ECRC Generation 和ECRC Check 默认不使能，用户可选。这
个选项是用来设置是否产生或检查PCIe 的TLP Digest 。 
2. Device Serial Number Capability 
Device Serial Number Capability 默认不使能，用户可以选为使能或不使能。 
具体的Serial Number 的设置，请参考《UG913_安路科技PH1A 系列FPGA PCIE 用户手册》的寄存
器表格。 
3. ARI Capability(EP Only) 
ARI Capability 默认不使能，用户可以选为使能或不使能。 
4. SR-IOV Capability(EP Only) 
SR-IOV Capability 不需要用户单独选择。当Physical Function0 的SR-IOV 或Physical 
Function 1 的SR-IOV 被使能时，PF0 的SR-IOV Capability 或PF1 的SR-IOV Capability 就会被自动
设置为使能。

5. TPH Capability 
TPH Capability 默认不使能，用户可以选为使能或不使能。 
6. Secondary PCIe Capability 
Secondary PCIe Capability 无需单独设置。当用户选择PCIe Generation 为Gen1 或Gen2 时，

10. DPA Capability(EP Only)

员的指导下使用。

ID Init Values 
1. Vendor ID 
Vendor ID 需要用户输入4 位十六进制值。默认的Vendor ID 是1EDB，为公司专属的Vendor ID。 
PCI-SIG 组织统一编制各厂商的Vendor ID。Vendor ID 作为PCI 设备身份的标识，是唯一的。 
2. Device ID 
Device ID 需要用户输入4 位十六进制值。 
Device ID 是设备本身代码的标识。如果用户要区别自己的不同型号的设备。 
3. Revision ID 
Revision ID 需要用户输入2 位十六进制值，是用户设计的修订版本号。 
4. Subsystem Vendor ID

Subsystem Vendor ID 需要用户输入4 位十六进制数值。 
跟Vendor ID 类似的，Subsystem Vendor ID 是PCI-SIG 组织认证的子系统制造厂商的标识码。作
为PCI 子系统身份的标识，也是唯一的。 
5. Subsystem Device ID 
Subsystem Device ID 需要用户输入4 位十六进制数值。 
Subsystem Device ID 是子系统代码的标识，用来区别自己的不同型号的子系统。 
Class Code 
系统会通过读Class Code 来判断PCIe Device 存在不存在。全0，系统会判定设备不存在。因此，
请一定要设置Class Code，不要保持Class Code 默认为“Unclassified device”，即全0。 
另外，系统会通过ID 和Class Code 来加载设备驱动。 
IP 界面里提供了最新的Class Code/Sub-Class Code 的可选项，根据用户选择设备的类型，Class 
Code/Sub-Class Code 就会自动显示。Class Code、Sub-Class Code 和Programming Interface Value
一起，显示在最下面的Class Code 文本框里。 
1. Base Class Menu 和Base Class Value 
用户选Base Class Menu 下拉菜单，Base Class Value 的2 位十六进制值就自动出现在文本显示
框中，同时也作为Class Code 的前2 位十六进制数显示在Class Code 的文本框里。 
如果Device Type 选中为Root Port of PCI Express Root Complex，Base Class Menu 只能选择
为Bridge(06H)。 
2. Sub-Class Menu 和Sub-Class Value 
Base Class 下细分为一个或多个Sub-Class。 
用户选Sub-Class Menu 下拉菜单，Sub-Class Value 的2 位十六进制值就自动出现在文本显示框
中，同时也作为Class Code 的中间2 位十六进制数显示在Class Code 的文本框里。 
3. Interface Value 
Sub-Class 下细分为一个或多个Programming Interface。 
Interface Value 需要用户输入2 位Programming Interface 十六进制数值。 
Programming Interface 因为选择项太多，本IP 没有提供Programming Interface 下拉菜单。

BAR setting 
如果用户把Device Type 设置为PCI Express Endpoint，BAR0~5 的Type 只能选为memory；如果
用户把Device Type 设置为Legacy PCI Express Endpoint，BAR0~5 的Type 可选为memory 和IO。 
首先，用户可以单独使能BAR0~5 中的一个或多个。 
当BAR0/2/4 的Type 为Memory 时，64-bit 可被使能或不使能，Prefetchable 可被选为使能或不使
能。当BAR0/2/4 为IO 时，64-bit 不能勾选，Prefetchable 不能勾选。Size 的可选范围是2^7 (128) 
Bytes 到2^1  (2) G Bytes；当BAR0/2/4 为IO 时，Size 的可选范围是2^2 (4) Bytes 到2^8 (256) 
Bytes。 
当BAR1/3/5 的Type 只能为Memory，且Size 的只能选择2^6 Kbytes。 
Device Type 设置为PCI Express Endpoint 或Legacy PCI Express Endpoint 时。用户可以选择
每个BAR 的数据通路，Local Bus 选择ELBI(convenient bus for register access) 和Other TX/RX 
Bus（High bandwidth bus）。 只能存在一个BAR，使用ELBI 总线，其他均使用Other TX/RX Bus。 
Device Type 设置为Root Port of PCI Express Root Complex 时， 仅有BAR0 被使能，且无法使
用ELBI 总线。 
用户设置完以上的选项后，BAR Value 就以十六进制数自动显示在Value 后的文本框里，供用户参
考。 
Expansion ROM 
用户可以通过选择框来使能Expansion ROM。 
Expansion ROM Size 的设置范围是2^1 (2) Kbytes~2^4 (16) Mbytes。用户设置好Size 后，BAR 
Value 就以十六进制数自动显示在Value 后的文本框里，供用户参考。

4 IP 应用注意事项 
4.1 实施注意事项 
4.1.1 约束 
PH1A 的PCIe 硬核的位置是固定的，因此不需要位置约束。 
PH1A 的core_clk 在Gen1/Gen2/Gen3 时，分别是62.5/125/250MHz。如果用户使能Include Pipeline 
Logic，IP 在生成时，会自动生成sdc 文件约束core_clk，否则需要用户对此时钟做频率或周期约束。 
4.1.2 txt 文件 
IP 生成.v 的同时，会生成要给同名的.txt 文件。请确保这两个文件是放在同一个目录下。如果
同名的.txt 文件未被TD 软件检测到，用户配置PCIe 的信息将不会出现在位流文件里。 
4.1.3 dat 文件 
PCIE IP 的配置信息是由IP GUI 生成的.txt 文件来控制的，当FPGA 上电后，会从bit 流中自动
加载.txt 文件信息，如果复位PCIE IP，会清空PCIE 的配置信息，导致PCIE IP 处于上电默认状态。 
PCIE GUI 提供了一种PCIE 自恢复方案，将dat 文件用作Rom 的init file,且在PCIE IP 复位
后，将Rom 中的信息通过DBI 写入到PCIE IP 中，即可实现自恢复，需要使能Include Pipeline 
Logic。 
4.2 仿真注意事项 
4.2.1 库的编译 
PH1A PCIe 的仿真文件是.sv 文件，但是其中包含了.sv 的模块。因此，建议用户在编译库的时
候，请选中System Verilog 支持。 
对应PH1A400，无论封装，仿真模型为ph1a_phy_pcie_v2.sv 
对应PH1A90 和PH1A180，无论封装，仿真模型为ph1a_phy_pcie_v3.sv 
4.2.2 配置文件 
有些仿真软件，比如Modelsim 或Questa，需要把IP 生成的.txt 和.dat 文件拷贝到仿真目录
下，这样配置信息才能被加载到仿真模型，从而获得跟上板一致的仿真功能。
