1 概述 
TangDynasty®（TD）支持使用Tcl 命令行或Tcl 脚本来执行FPGA 设计流程。本文介绍TD 支持的T
cl 命令以及使用方法。 
2 Tcl 命令及脚本的运行方法 
2.1 在 TD 界面模式下 Console 窗口运行 
GUI 界面的Console 窗口可以运行Tcl 命令。 
 
图 2-1 Console 窗口运行 Tcl 命令 
注： 
1. 在Console 窗口中，Tcl 命令须在适当的阶段运行。例如，在open_run phy_1 后不能在Console
窗口运行Syn 阶段的Flow Step 命令(elaborate/optimize_rtl/optimize_gate 等)。

3 Tcl 脚本运行工程 
本章介绍如何使用 TD Tcl 脚本运行整个流程。脚本类型分为工程模式和非工程模式。TD 工具支持
在当前工程中导出Tcl 脚本。 
3.1 工程模式 
工程模式需要先用Tcl 命令创建一个TD 工程，基于此工程管理的方式来进行后续流程的命令。 
3.1.1 工程模式脚本结构 
1. 创建工程（create_project） 
2. 设置工程top module 名字（top_module） 
3. 添加源文件和约束文件（add_files） 
4. 如果需要多个run，添加run（create_run） 
5. 创建工程后，syn_1 和 phy_1 是默认就存在的，不需要再创建。 
6. 设置参数（set_param） 
a） multi run 模式下set_param 命令需使用-run 选项指定参数设置对应的run 名称。 
b） 可以使用set_seed_param 为active run 设置multi seeds，同时需要设置enable_seed 参
数为on 
7. 启动运行并等待运行结束（launch_runs, wait_run） 
8. 筛选并保存最好结果（save_best_bits） 
9. 关闭工程（close_project） 
3.1.2 工程模式脚本示例 
以下为包含multi runs 和multi seeds 功能的脚本示例： 
set proj_name test 
set top run_led 
     
If {[file exists “${proj_name}.al”]} { 
    # If project exists, open the project. 
    import_device ph1_100.db -package PH1A100SFG676 -speed 2 
    open_project ./$proj_name.al 
} else {

3.3 使用现有工程运行 single run 模式 
在现有工程中，源文件完成添加后，可以直接使用此工程以single run 模式运行流程，省去添加
源文件的步骤。 
3.3.1 single run 脚本结构 
1. import_device 
2. 以single run 模式打开工程（open_project） 
3. 设置参数（set_param） 
4. 添加约束文件（read_adc/read_sdc） 
5. 运行综合阶段分步命令以及每个步骤后需要产生各种报告和输出文件的命令 
6. legalize_phy_inst 命令 
7. 布局布线阶段分布命令以及每个步骤后需要产生各种报告和输出文件的命令

4 Tcl 命令 
本章按照Tcl 命令的功能类别介绍各命令的用法。 
4.1 工程管理 
4.1.1 import_device 
导入所使用的device。 
4.1.1.1 命令参数  
import_device -package <package_name> [-speed <speed_number>] db_name 
4.1.1.2 参数释义  
 -package <package_name>:（必选）指定导入device 的型号及封装 
 -speed <speed_number>:（可选）指定导入device 的速度等级。若未使用此选项则使用该器件默
认速度等级。 
 db_name:（必选）指定导入device 的db 文件名。 
查找db 文件名称的方法：以此device 创建的现有工程中，打开syn run 或 phy run 的 log 文件
（<project_name>_Runs/syn_x/run.log 或<project_name>_Runs/phy_x/run.log） ，搜索import_
device，此命令行中可找到device 的db 文件名或直接复制import_device 命令行。 
4.1.1.3 命令示例  
import_device ph1_100.db -package PH1A100SFG676 -speed 2

4.1.22 set_seed_param 
为active phy run 配置multi seed，仅在multi run 模式的脚本中有效。multi seed run 具有
非易失配置属性，未被重新写入前将自动保持并使用上一次有效的设置。 

 
 
TangDynasty® TCL Command User Guide  
SWUG105 www.anlogic.com 25

4.1.22.1 命令参数  
set_seed_param [-num <int>] [-init <int>] [-step <int>] [-jobs <int>] [-save <int>] 
[-endStep <place/route/bitgen>] [-genBit <on/off>] [-disable] [-random <on/off>] [-filter
 <on/off>] [-rwns <double>] [-pwns <double>] [-congestion <int>] [-farm <on/off>] [-tool 
<bsub/dsub>] [-ip <lsf_server_address>] [-queue <lsf_queue_name>] [-A <account_name>] 
4.1.22.2 参数释义  
 -num <int>:（可选）设置seed 的数量，类型为整数，默认为1。 
 -init <int>：（可选）设置最小的seed 值，类型为整数，默认为0。 
 -step <int>：（可选）设置seed 之间的步长，类型为整数，默认为10。-random 与-step 是互斥
的，同时使能时按-ramdom 执行。 
 -jobs <int>：（可选）设置允许同时运行的seeds 数量。Farm 上运行时自动开启为最大并行数
量。类型为整数，默认为3。 
 -save <int>： （可选）设置运行结束后保留的seeds 数量，类型为整数，默认为1。 
 -endStep <place/route/bitgen>:(可选)设置multi-seed runs 运行目标step，默认为route。 
 -genBit <on/off>： （可选）是否生成bit 文件，默认为on。 
 -disable： （可选）对于已经使能multi seed 的工程，通过此选项关闭multi seed。 
 -random <on/off>： （可选）是否随机生成seeds，默认为off。-random 与-step 是互斥的，同时
使能时按-ramdom 执行。 
 -filter <on/off>： （可选）是否开启过滤功能，通过过滤功能可以提前结束不合理的seeds。默
认为off。当此选项设置为on 时，根据-rwns，-pwns，-congestion 指定的阈值来判断是否提前
结束。 
 -rwns <double>：（可选）设置route 的wns 阈值，当-filter on 时，route 阶段的wns 小于该阈
值的seed 将被提前结束。默认为0，单位ns。 
 -pwns <double>：（可选）设置plac 的wns 阈值，当-filter on 时，place 阶段的wns 小于该阈
值的seed 将被提前结束。默认为0，单位ns。 
 -congestion <int>：（可选）设置congestion 的阈值，当-filter on 时，congestion 值大于该
阈值的seed 将被提前结束。默认为100，表示布线资源被100%占用。 
 -farm <on/off>:（可选）是否开启farm 运行，默认为off。 
 -tool <bsub/dsub>：（可选）设置使用bsub 或dsub，根据LSF 配置的命令决定，默认为bsub。 
 -ip <lsf_server_address>： （可选）开启farm 时，设置LSF 服务器地址。 
 
 
TangDynasty® TCL Command User Guide  
SWUG105 www.anlogic.com 26 
2026.01   
 
 -queue <lsf_queue_name>：（-farm on 时此选项必选）开启farm 时，设置LSF 工作队列的名
字。 
 -A <account_name>：（-tool dsub 时必选）当-tool dsub 时，指定account 的名称。 
4.1.22.3 命令示例  
1. 以下示例设置10 个seed，从 seed_0 开始，seed 步长为10，同时并行运行最多5 个job，最终结
果保留最好的2 个。 
Set_seed_param -num 10 -jobs 5 -save 2 
2. 以下示例设置6 个 seed，从seed_5 开始，seed 步长为5，同时并行运行最多3 个job，使用far
m 的dsub 命令，设置queue 为normal，account 为user1. 
Set_seed_param -num 6 -init 5 –step 5 –jobs 3 –farm on –tool dsub –queue normal \ 
-A user1

4.3.1.1 命令参数  
read_hdl [-help] [-file <file_path_name>] [-dir <dir_path>] [-global_include <global_
include_file_path_name >] [-included_dir <included_dir_path>] [-define <define_name/defin
e_name=define_value>] –top <top_module_name> 
4.3.1.2 参数释义  
 -help:（可选）打印帮助信息。 
 -file <file_path_name>
1，2
：（可选）指定读入的一个或多个源文件的绝对路径或相对路径及文
件名，支持.v,.sv 和.vhd，TD 会根据文件后缀自动选择对应的语言标准。解析多个文件时需要放
在双引号""中，不同文件之间用空格分隔。

 示例2：read_hdl -file "sv::in1.v"，无视后缀，按照SystemVerilog 的语法解析 in1.v； 
 示例3：read_hdl -file "vlib::lib1::in3.vhd", 按 VHDL 库 lib1 解析in3.vhd。 
 -dir <dir_path>
1，2
：（可选）读入并解析指定目录中的所有文件。 
 -global_include <global_include_file_path_name>2： （可选）设置全局include 文件,global_
include_file_path_name 为全局include 文件的绝对路径或相对路径及文件名。 
 -included_dir <included_dir_path>
2
：（可选）设置include 文件所在的文件夹名称。 
 -define <define_name/define_name=define_value>：（可选）设置宏定义。宏定义的设置有两种
方式：声明-define <define_name>和赋值-define <define_name=define_value>。当同时设置多
个宏定义时，需要加在""内，不同宏定义之间用空格分隔。 
 示例1：read_hdl -define NAME 的含义是声明一个名为 NAME 的宏定义； 
 示例2： read_hdl -define NAME=VALUE 的含义是声明一个名为NAME 的宏定义并赋值为VAL
UE; 
 示例3：read_hdl -define "NAME1 NAME2=VALUE2" 的含义是声明一个名为NAME1 的宏定义，
声明一个名为NAME2 的宏定义并赋值为VALUE2;

4.5.1 create_clock 
定义一个主时钟，同时指定其属性，如名称，周期，上升下降沿时间或占空比等。 
4.5.1.1 命令参数 
 -name {<clock name>} 
 -period <time ns> 
 -waveform {<rise time ns> <fall time ns>} 
 [<Target>] 
 -add 
4.5.1.2 参数释义 
 -name {<clock name>}：用于指定时钟名字，该名字将用于时序分析和其它时序约束命令中的使
用。该参数不能省略，否则报错。 
 -period <time ns>：用于指定时钟的周期，时间单位为纳秒（ns） ，数值为正，数字格式是保留
小数点后三位。 
 -waveform {<rise time ns> <fall time ns>}：用于指定时钟第一个上升沿与第一个下降沿的时
间点，可以指定不同相位或者不同占空比，时间单位为纳秒（ns） ，数字格式是保留小数点后三
位。如果省略该参数，TD 时序分析工具将该项默认为相位为零，占空比为50%的时钟波形。当设
置的时间点不在周期内时，TD 时序分析工具将报错提醒。 
 [<Target>]：用于指定时钟在FPGA 内的时钟源点，一般对象是I/O 管脚（可以使用get_ports 来
约束）或者FPGA 内硬核的时钟管脚（可以使用get_pins 来约束） 。 
 -add：用于指定对同一时钟对象进行多次约束，可以约束为不同的频率、不同的相位或不同的占
空比，一般用于时钟MUX 的约束。如果省略该参数，并且用户对同一时钟对象进行了多次约束，T
D 时序分析工具将最后的一次约束覆盖之前的约束。

除上述GUI 窗口设置和set_param 命令设置方式外，General Option 还可以使用bitgen 命令行的
下列options 设置： 
 -bit <bitfile_path_name>:（可选）指定bit 文件的绝对路径或相对路径及文件名。-bit 和
-bin 两个选项需至少使用一个。 
 -bin <binfile_path_name>：（可选）指定bin 文件的绝对路径或相对路径及文件名。-bit 和
-bin 两个选项需至少使用一个。

界面显示的 version 值来判断当前芯片加载的 bit 文件。使用此选项时需同时使用-bit 或-b
in 选项。此选项的值为2 位16 进制数值，默认值为00. 
 -security：（可选）屏蔽SRAM 回读功能。 
 -no_date_info：（可选）bit 文件不写入文件创建时间信息，用于在比较不同bit 文件时忽略
时间戳的影响。 
 -compress：（可选）bit 文件压缩。 使用此选项时需同时使用-bit 选项， 会同时生成非压缩的
bit 文件和压缩的bit 文件。 
 -embedded_compress：（可选）bin 文件压缩，用于嵌入式加载。 
 -seu_all:（可选）开启全码流seu 检测功能。仅PH1A100 和 PH1A400 支持此选项，默认不开
启。 
 -unused_io_status <pullup/pulldown/keeper/none>：（可选）将实际逻辑中未使用的IO 启
动状态统一设定，默认值pullup。
