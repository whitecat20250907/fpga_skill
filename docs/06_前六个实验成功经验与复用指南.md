## 3. 统一开发流程：VS Code → TD → BitWriter → 观察

1. **VS Code 改源码。** 打开目标工程的 uisrc/01_rtl；普通可复用模块/IP 依赖在 uisrc/03_ip；仿真在 uisrc/02_sim；引脚与时序在 uisrc/04_pin。VS Code 里打开了哪个文件，不决定 TD 正在编译哪个工程。
2. **TD 打开正确的 fpga_prj.al。** 查看根目录、器件、顶层和当前约束集；更换例程后核对标题与路径。新文件要加入工程，不能只在资源管理器创建。
3. **运行综合 syn_1。** 出错查看 run.log 最先出现的具体错误；检查模块、文件、参数、许可。
4. **运行物理实现 phy_1。** 完成布局、布线、时序分析和 bitgen。检查 setup/hold、时钟和约束，不只看进度条到 100%。
5. **找到本轮 bit。** 通常是 `<工程目录>/fpga_prj_Runs/phy_1/fpga_prj.bit`；压缩版为 fpga_prj_compress.bit。VS Code 工作区隐藏了部分生成目录，左侧不显示不等于没有生成，使用系统文件管理器或完整路径查看。
6. **BitWriter 下载。** Refresh 识别器件；PROGRAM_SRAM；添加本轮 bit；Run；看到下载成功后再检查功能。5 MHz 是 JTAG 下载时钟，不是设计时钟。SRAM 程序断电丢失，Flash 固化是后续独立步骤。
7. **按外设验收。** 串口看真实回包、I²C/DDR 看有效波形与数据、屏幕看图像。下载成功只证明位流写入，不自动证明外设工作。
8. **保存结果。** 记录连接、版本、源码、bit 哈希、时序、成功现象。新功能在副本修改，原六份作为对照。

带 ChipWatcher 的实验还要使用与探针配置配套的调试 bit，常见位置为 phy_1/cw/compiled.bit。不能只换 bit 不换探针配置。

## 4. 实验 01：UART 回环

**打开：** examples/01_uart_loop/fpga_prj.al，顶层 uart_top。

| 信号 | FPGA 球号 | 电平/意义 |
|---|---|---|
| I_sysclk | T16 | LVCMOS18，25 MHz |
| O_uart_tx | U11 | LVCMOS18，FPGA 发往 PC |
| I_uart_rx | V11 | LVCMOS18，PC 发往 FPGA |

下载后选择 FPGA 对应串口，115200、8 数据位、无校验、1 停止位、无流控。此前 COM11 是当时识别值，以当前设备管理器为准；不要混成 RK3576 控制台串口。

关闭串口工具的本地回显，发送 111、999 等内容，在接收区检查相同数据，结合 TX/RX 计数判断。**这个程序不会上电主动打印欢迎语**，没发送时显示空白正常。成功经验是“实际收回发送字节”，不是发送框本身有文字。

可复用 ui_uart_rx、ui_uart_tx；新增多个发送源时加队列和忙判断，原回环不保证任意压力下永不丢字节。

已建立独立自检：uisrc/02_sim/verified。40 ns 时钟、等待复位后发送 55/AA/00/FF/31/95，6 字节比较通过，运行 2 ms。原作者 cmd.do 不作为本机成功入口。

## 5. 实验 02：I²C EEPROM 与 ChipWatcher

**打开：** examples/02_i2c_eeprom/fpga_prj.al，顶层 eeprom_test。时钟 T16/25 MHz，SCL=N14、SDA=U16，LVCMOS18。目标 24C02 的 7 位地址 0x50，原写地址字节 0xA0。

原工程缺少主时钟 SDC，已补 timing.sdc 的 40 ns 并登记 constraint_1。复制时带上，别只拷 Verilog。

ChipWatcher 的两个“+”用途不同：

- **上方波形工具栏绿色 +：** 把已存在于调试核中的信号加到显示列表。
- **下方 Trigger Setup 的 +：** 把已存在的信号加入触发条件。

已有信号可以直接选择显示；要看未编入 CWC 的新内部信号，需修改调试核并重新编译下载，不能仅在窗口点加号得到。

本实验触发条件采用 TS_S[2:0] `==` `[B]101`，表示二进制 5。触发次数增加说明已经捕获一次；游标处状态为 101 本身正常。再看 rd_data[7:0] 与 wr_data[23:16] 是否相同，iic_bus_error/iic_error 是否异常。窗口太窄看到平线时缩小视图，不能据此断言状态机没走。

TS_S=5 是等待阶段，便于看稳定读回值；真正判定还要结合数据与错误，零错误单点不是连续无错证明。未来做可靠参数存储增加重试、写完成判断和累计错误。

## 6. 实验 03：RTC 时间串口输出

**打开：** examples/03_iic_rtc/fpga_prj.al，顶层 rtc_clock_ds1337。时钟 T16，I²C N14/U16，UART TX U11，均按原约束。

DS1337 的 7 位地址 0x68，原地址字节 0xD0。程序每次启动设置 12:00:00，然后周期读取、格式化并串口发送；115200/8N1，可观察类似 12-00-00 的时间变化。

以后需要“断电后继续走时”，不能照搬每次启动重设时间的逻辑，应加入是否初始化/命令设时的策略，并单独验证 RTC 供电。当前成功结论是原例程运行成功，不包含未做的掉电验收。

与 EEPROM 集成时共用 N14/U16，必须一套 I²C 主机加事务调度；不能各复制一套控制器同时驱动同一总线。RTC 的串口也与 UART 共用 U11，统一发送调度。

原 uart_tx_block 计数边界和时间更新拍次存在需复用时核对的细节，skill 已记录。整理阶段保留已跑通 RTL，不悄悄修订成未经测试的新版本。

## 7. 实验 04：DDR3 FDMA

**打开：** examples/04_ddr3_axi_fdma_test/fpga_prj.al，顶层 example_top。DDR 输入参考为 T13/T14 差分 100 MHz，主 SDC 10 ns；物理 DDR 引脚由 IP 自带约束处理，不只在顶层 ADC 中寻找。

必须等待 S_ddr_init_cal_done 后读写。捕获 I_fdma_rvalid 等有效条件，结合 rbusy、rready、T_S 和读数据看状态。

已见截图：rbusy=1、rvalid=1、rready=1、T_S=011，读数据在递增，用户报告 test_error=0。前一截图某点 rcnt=640、rdata=639，不能直接判失败：比较器有有效延迟，必须按有效拍对齐。

**这次通过范围是 DDR 基础读写链路。** 原比较器只比较低 16 位，test_error 为非粘滞脉冲；原 TEST_MEM_SIZE=2 GiB 与物理 x16/2 Gb=256 MiB 不一致。因此不能将此次结果写成“全 2 GiB、全 128 位、所有地址压力测试通过”。

后续存储模块按实际容量做地址分区，加入错误累计、全位宽数据模式与边界验证。复用 ui_FDMA 时读取实例真实位宽，不使用默认参数猜测。

## 8. 实验 05：7 寸 DSI 测试图

**打开：** examples/05_tpg_dsi_7cun/fpga_prj.al，顶层 system_top。25 MHz 输入，配套 7 寸屏接 VID005 的 FPGA DSI；底板 RK DSI 不承载这份 FPGA 程序输出。

成功现象是屏显示测试图并切换模式。有效区域 1024×600，总时序 1344×635；S_tgb_mode 从 0 至 9 循环，每 121 帧切换。没有用物理仪器实测帧率，不能只根据模式切换推断具体帧率。

带上 PLL、DSI 控制逻辑、屏初始化 ROM 及数据文件。新图像源先维持原 RGB/DE/HS/VS 时序，单独替换源；不同时改屏参数、PLL 和像素格式，方便定位问题。

## 9. 实验 06：IMX415 → FPGA → DSI 屏

**打开：** examples/06_csi_2_dsi_imx415_7cun/fpga_prj.al，顶层 system_top。用户已确认相机为 IMX415、连接 VID005，并确认此实验成功。

```text
IMX415 配置与采集
  → 4 lane MIPI RX / CSI 解包
  → RAW10 / ISP
  → 像素打包 / DDR 帧缓存
  → 读出显示区域 / DSI
  → 配套 7 寸屏
```

这是今后项目最合适的起点，内部已经有 DDR 和 DSI，不需要再把 04/05 顶层合并进去。

主要硬件控制脚：相机 SCL B14、SDA A14、复位 O_clk_rst B18、相机时钟 S_clk_25m A18。系统 25 MHz T16，DDR 参考 T13/T14；CSI/DSI 高低速引脚以及 IP 的 DDR 引脚在 skill 的完整索引中逐文件列出。

当前缓存按 1080 行组织写入，显示读出 1024×600 且行步进 1920。**屏幕显示成功不等于完整 1080p 全幅缩放显示，也不等于已经测得采集帧率。** 要做 ROI、时间戳、高帧率必须再核算像素、行、帧及链路带宽。

复用前必读的两个配置问题：

- PLL 的 IPC 中 C0 写 70 MHz，而当前生成代码参数推得 75 MHz，顶层还叫 S_clk_70m；SDC 对 C0/C1 的名字与顶层互换。先保存这套能工作的产物，修改时再交叉核对并统一，不能随手重新生成覆盖。
- 原时序文件使用较宽泛的 exclusive clock groups。新加跨时钟数据不能靠继承这些例外绕过分析，应做正确 CDC 和时序审查。

第六例编译较久不必重复点运行。看本轮日志是否在推进、是否有明确错误，等物理实现结束再下载。
