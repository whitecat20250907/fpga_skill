## 5. 最终系统结构与职责

```text
IMX415 摄像头
  → FPGA CSI / ISP
  → 独立高清预览 + 同源模型平面、检测输入
  → PCIe
  → 唯一 C 所有者（采集 / DMA / BAR / 共享环 / 显示提交）
  → 眼脸、手部 NPU 服务
  → CPU 交互引擎
  → 应用适配器
  → 医学演示 / 游戏 / 桌面 / 基础展示

HDMI、网页、MIPI 消费统一交互状态
FPGA 同时承担 MIPI 算法可视化
RK GPU 承担医学三维画面的图形渲染
```

- FPGA：相机采集和 ISP、共享缩图、128×128 / 192×192 检测输入补边缩放、ROI 测光、匹配 765 的曝光控制接口、MIPI 可视化等。
- 双核 NPU：脸、眼、手等网络的模型推理；不能笼统称为“所有算法都在 NPU”，后处理和交互仍有 CPU 工作。
- CPU：唯一采集所有者、共享帧与消息编排、关键点后处理、标定与滤波、眼控目标吸附、手势状态机、动作执行、应用控制。
- GPU：RK3576 本身有 GPU，项目历史中已核对 Chromium/Mali 图形链。可以描述医学三维渲染；不得因此编造 GPU 忙碌率或把 NPU 写成渲染器。
- 同源图像供脸、眼、手复用；眼动输入复用人脸和关键点结果。多轻量模型协作、按需启用，比单独强调八类轨迹模型很小更符合用户要求。

最终八个核心服务：`hmi-fpga-io`、`hmi-gaze`、`hmi-hand`、`hmi-engine`、`hmi-ui`、`hmi-hud`、`hmi-adapters`、`hmi-console`。另有 `hmi-autostart920.service` 编排开机恢复。

目标机路径：`/userdata/hmi_v2`。统一入口为该目录下 `tools/hmi up` / `tools/hmi down`。配置使用的原 Python 路径为 `/userdata/gaze_model_migration_v1_20261014/app_venv/bin/python`，**环境没有打进代码包**。

## 6. 必须保留的最终交互语义

这是多次用户纠正后的体系。旧说明里出现的左手确认、每次必须重新登记、重复动作要求手不离镜等，都可能已经过时。

### 6.1 手势和轨迹

- 右手是主要操作手：握拳进入手势识别；伸食指切换轨迹识别。
- 静态手势：右手握拳 → 做手势 → 握拳确认，执行绑定动作。
- 轨迹：右手握拳准备 → 伸食指绘制 → 握拳结束；识别成功后直接执行，不再要求左手确认。
- 左手已取消全部业务确认功能，只保留重复和撤回快捷动作。
- 左右手均支持：张掌 → 握拳，重复上一次动作；张掌 → 拇指向下，撤回上一次动作。
- 上一次动作需要保留，手离镜很久再回来仍可使用重复/撤回，不应重新变成“离镜就清空”。动作是否支持撤回仍需遵循现有适配器能力。
- 旋转：触发绑定动作后持续旋转；**操作手张掌或离镜即停**。
- 不要恢复之前复杂的旋转轴切换、窗宽窗位、前后切片等手势菜单。

### 6.2 眼控接管

用户最终要求只保留一个眼控功能名称：**眼控接管**。不要再次拆成“预览眼控目标”“目标吸附”“开始聚焦”等多个近义入口。

1. 右手触发并确认眼控接管。
2. 眼动在这一小段时间启用，依据注视位置和置信信息选择可操作目标，目标闪烁/高亮。
3. 操作手再次握拳，结束本段眼控并锁定当前目标。
4. 锁定后鼠标停在该目标，等待点击/结构聚焦等手势；只有下一次眼控接管才继续移动。
5. 头部/面部可视化应独立保留，不应因为眼动按需暂停而整个脸部链路消失。

历史上发生过“已经锁定，点击/聚焦仍提示请先眼控接管并锁定”的状态不一致，以及“锁定后旋转冲突”。不要通过重新开启眼动、清空锁定点、增加确认层来掩盖这类问题。应检查动作需求、目标锁存、状态消费和应用回执是否一致。

### 6.3 双指缩放

旧的放大/缩小指令体系被用户要求删除并重做：

- 双手食指竖起，连续确认 3 帧，记录初始指尖距离 x。
- 当前距离为 y，本次相对缩放倍率 y/x。
- 放下手指保持当前大小；再次举起，从保留后的大小继续缩放。
- 应保留与旋转停止、轨迹进入、张掌快捷键之间的既有仲裁，不能让一个动作同时进入两条交互分支。

## 7. 显示与医学演示约定

- **MIPI 是算法展示，HDMI 是实际交互。** 用户平时不一定看 MIPI，因此 HDMI 右下角操作小窗、锁定状态、执行回执必须能独立支持使用。
- MIPI 保留用户认可的旧布局：左右手实体图形、头部、眼睛与屏幕相对位置、轨迹区域及八类结果。用户明确取消在 MIPI 强行堆满 478 点。
- 478 点面部特征展示放在 HDMI 基础功能页面。基础页面还展示预览、模型叠加、头/眼/手 ROI、帧率与资源观察。
- HDMI 左上角有实时识别小窗，用于展示小人脸/眼睛也能捕捉；操作无关的大标题、教程长句应尽量精简。
- 医学展示讲清“病例选择 → CT 与三维结构对照 → 注视选择部位/病变 → 点击聚焦 → 旋转、缩放观察 → 翻页/诊断选择”的故事。
- 病例 1/2/3 应对齐；眼控目标应有合理间隔、大小适度，不能为了“分散”随意上下错位。
- 可点击目标应是医学内容、部位、影像对照和诊断选项，不要把已有手势的放大、缩小、上一页、下一页按钮再次堆上 HDMI。
- 三维标签箭头需指向对应模型位置，并随旋转变化；不能只留二维图片而把三维模型弄丢。
- 游戏与医学切换应正常全屏显示目标应用，避免单纯叠盖导致用户以为切换失效。
