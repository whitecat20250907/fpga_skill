## 实际分工

让FPGA逐帧产生低延迟、可核对的ROI和测量量，RK用这些测量与模型结果做交互。当前37相机约60fps，06本版接受SOF实测约55.56fps；FPGA内部加速和缩小ROI不自动提高传感器物理帧率。新方案先以实际稳定模式为基线，4K和传感器移动开窗另行签核。

| 工作 | FPGA实现 | RK实现及原因 |
|---|---|---|
| 像素前端 | 保留已验证CSI/PAD相位、复位、RAW/ISP及真实ready；统一帧号、SOF时间和错误计数 | 严格解包，保留source身份和序号，丢旧帧策略与链路丢帧分开 |
| 三种基础预处理 | 4像素/拍亮度、两行3×3高斯、分bank上一帧直方图均衡；每路有bypass和明确边界策略 | 算法golden与模型输入归一化；处理LUT首帧identity及曝光变化 |
| 眼与脸ROI | 双眼256×128及脸448×448；坐标校验、裁切、奇偶Bayer处理、帧边界原子提交、配置序号与过期保护 | 人脸/眼角/手检测、跟踪和ID，经已有控制通路反馈ROI。默认无可信ROI时不得伪造眼坐标 |
| 眼区快速特征 | 眼窗直方图低分位阈值、二值化、3×3形态学、面积/一二阶矩、bbox、SAD、亮暗/反光比例；有界连通域择优并输出overflow/invalid | 除法可在RK完成；使用面积/遮挡/新鲜度降权。FPGA结果是眼区相对测量，不能直接叫绝对注视 |
| 快慢融合及预测 | 保留每帧采样戳/ROI版本/质量；可给定点位移和速度辅助量 | 注视模型、头姿/PnP、相机屏幕标定、标度K、语义吸附/预测与快慢融合。目标位置和个人偏差是动态高层数据 |
| ROI压缩与链路 | 可逆delta、受限LZ77、存储回退、逐行CRC、帧/ROI/timestamp/长度/flags；默认QUANT_BITS0 | 严格解码/长度/CRC/序号/位流绑定。若启用有损必须另训练/验证模型，不沿用无损误差声明 |
| 物理按钮与控制 | 2FF、按下/释放去抖、长按/连发事件；命令CRC/版本/序号、frame-atomic配置与watchdog | 普通板载KEY属于RK连接，RK读键并回传事件；手势识别/确认/仲裁/多用户/UI和语音均在RK |
| 真值IO | 同一64bit微秒时基锁存frame/event/photo，事件FIFO、overflow报告；舵机50Hz PWM及默认关闭/超时互锁 | 记录发起事件的来源与时间、显示角标及CSV，校准sensor行曝光和显示延迟 |

FPGA的价值可直接演示：RK慢模型尚在运行时，每个真实源帧的眼区特征仍持续更新，并附带共同时间戳与质量；传输的ROI有效字节减少，CRC/溢出可以核对。不能先假定两芯片“刚需”或60Hz高于全部普通相机，必须与RK纯软件同场景/同输出质量测量比较。

## 方案中应修正的预算与测量含义

1. 本机当前PH1A90SEG324 −2的实际TD route报告给出LUT6 64320、ERAM20K 272、DSP 240；06使用14194 LUT6、61 ERAM、56 DSP。方案的115k LUT不能作为该工程资源预算。新例程各自保存自己的route报告，不能套用此06用量。
2. 双眼GRAY8@60是31.46Mb/s，脸GRAY8 448²@30是48.17Mb/s，合计79.63Mb/s。若脸模型保留RGB888，脸为144.51Mb/s、总176Mb/s。灰度输入模型必须确认训练/量化一致；ROI率的分母写RAW10/RGB/YUYV，不能混用。灰度总量对1080@60 RAW10约6.4%，仅裁切尚未满足方案“≤5%”，压缩后再实际测。
3. 整块脸RGB双缓冲约1.20MB，超过本芯片BRAM总量；先用行级流式压缩/现有DDR，眼窗缓冲与滤波分配片上RAM。资源够用、NPU并行时延和MIPI速率都是需测假设，不只有I2C一个风险。
4. Sony官方资料列出IMX415窗口裁切和binning模式；它不提供本模块运行中更新窗口的寄存器事务和生效时序证明。先验证该模组寄存器表、group hold/帧界生效、Bayer相位及MCLK/实际FPS；未证明之前保持已验稳定配置。[Sony IMX415资料](https://www.sony-semicon.com/files/62/pdf/p-12_IMX415-AAQR_AAMR_Flyer.pdf)
5. 帧SOF戳到显示光电是“帧参考→光子”延迟；手指真实动作在曝光窗内的具体时刻尚未知，不能仅靠该差值称完整“动作→光子物理真值”。若要后者，用可观测的共同电触发/光刺激及双端探头，另报告曝光/滚快门、输入同步和探头响应误差。
6. 眼跳预判、标定误差、三模型4–8ms、多人性能和≤50ms端到端均为方案目标；现有YOLOv5s约32ms不能认证另一模型组合的预算。用真实相机输入和本机模型分别验收，不能把NPU nominal算力折算成已达FPS。
7. ISO9241-9:2000已撤销，ISO列出9241-400与9241-411后继。可以采用并明确记录历史Fitts多方向点选协议作对照；9241-411的范围明确不覆盖gesture/voice输入的相关要求，不能把“跑了13目标环”写成整个系统ISO符合性认证。[ISO9241-9状态](https://www.iso.org/standard/30030.html)，[ISO9241-411范围](https://www.iso.org/standard/54106.html)
