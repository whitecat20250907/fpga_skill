# PCIe真实特征UI与相机共存

用于PH1A90SEG324上相机/PCIe仍需工作、增加DSI实时手头眼界面或源头缩图的情况。早期失败保留；2026-10-23完整源v12、有限DSI驱动采图及实际协议/内部UI与相机共存已过，真实特征/外部屏幕像素/NPU并行/长测仍待。不能把这些有限证据扩成整机通过；当前运行选择仍从仓库根CURRENT读取。

## 相同RTL不保证相同采样负载

组合UI后的最终设计使用222/272 ERAM；独立160+95相加的255只是预估。实际RAW trace从4 ERAM变成128个分布式RAM，PAD后第一层下降沿采样FF从每路4个变为9–16个。相机RTL、两颗LCLK参数/端口及全部10个相机PAD绑定相同，仍然出现0帧。这是实现差异，尚未证明因果。

`ram_style="bram(min_area)"`在本例没有强制保留RAM；原生日志SYN-2599明确说因资源限制改用dram。查看实际综合/门级和物理存储类型，不用属性文本或总ERAM余量替代核对。下一次先在gate阶段检查预期映射，再投入完整place/route。精确ERAM数量依具体实例的数据宽度/深度而定；本例16位×4096字的trace期望4颗，不是其它工程的通用阈值。

显式PH1_LOGIC_ERAM可用来保留敏感支路资源，但要核对模式、双端时钟、NOREG延迟、CE/WE、地址、字节使能和上电后完整覆盖。当前新例只在顶层明确`{16'd0,raw_nibbles}`处选16位，CSR仍零扩展回32位；不能把任意32位trace都截成16位。缩小容量、降低采样率或关闭DSI都不代替最终共存目标。

## 诊断只签实际覆盖范围

同一诊断位流高阻→输出→高阻，独立采集真正关闭/回收后才切换；内部DSI时钟保持运行。旧PAD诊断三轮lane3字节有效均0、校准窗口/RAW10/解析FS均0，而selected51前后各321帧。显式4ERAM后，完整native和每路4个首级FF核验虽通过，实板三轮仍0帧；lane3仅221/466/510个稀少对齐周期，RAW10/FS/成功窗口仍0。它不支持RAM已修复共存的结论。此结果没有建立DSI引脚驱动的可逆归因，也不能排除内部时钟或未测量电气因素。

差分负端可能隐式占用物理PAD，检查实际网表全部正负端位置，不能凭BGA相邻推断冲突。PAD参数相同、内部STA为正、I²C/MCLK已启动都不能证明外部串行采样正确。零CRC/ECC也可能只是从未收到包。保留采集开启时的相干快照、进度、原始nibble和完整恢复对照。

## 复用现有NPU特征

app32/app33中外层NPUFaceAlignment会对每个人调用底层MediaPipe几何辅助函数，然后选主脸。观察底层`MediaPipeFaceAlignment.detect`会发布每脸中间结果，可能不是当前主操作者。观察实际`gaze_runtime`绑定的外层`NPUFaceAlignment.detect`返回值，保留原返回对象、来源时间和采集序号；不新建摄像头或推理。

当前实现的两脸合同明确执行了实际外层代码：内层两次，外层只发布选定主脸一次。网络用桩的测试不签NPU/真人性能。失去脸应发布无效结果，旧帧/未来帧/重复帧不能重标为新鲜；可选UDP失败不能使主推理崩溃。

track ID不等于个人身份。HFT1此版只有一个头、双眼和两手；四手结果按左右最高置信度混选可能拼出两个人的手，不能签活动操作者关联。真实四手归属、标定和交接须独立解决。

## 源头area3小图

保留现用C合同：每通道九像素和，`(sum+4)/9`；RGB3字节序与ISP物理总线分别核对，不能用中心抽样或灰度图替代。当前独立流组件使用一行33位列累加，不需要全幅缓存；实际RAM/DSP与时序须TD测量。

现有ISP每拍四像素，单像素核不能仅靠接线就保证保留其吞吐。后续四像素area3用两个奇偶列同步RAM处理每拍1/2个连续水平三像素和，末一行输出1/2像素并显式带数量；两张不同全幅图的无阻塞/随机背压与实际C参考逐RGB一致。帧内新SOF必须同时重置横向和垂直相位，原反例曾在新帧第0行错误发出旧相位输出，已保留并修正。不是只有正常满帧一致就够。

字节绑定执行原selected51的padding和RGB24打包器作独立对照，红/绿/蓝/白及通道图案均核对，而非只测试新连线自身。四像素吞吐仍不签物理频率/实际RAM推断、源端整帧丢弃、预览与小图多流协议或NPU收益；同源ID/时间标签仍须有真实生成与映射依据。

不可停源的缩图支路不直接接核ready。被动FIFO输入应是原主链已接受beat的tap_fire；无上游ready，溢出清未读队列、丢弃至下一SOF，同时保持已提供的受阻输出。旧前缀可能继续送达，主机只在完整EOF及长度/CRC/来源验证后提交。有限RTL组合回归已证明旧受阻前缀不产生完整EOF、下一不同帧和复位后旧RAM不复活；不签任意阻塞下无丢帧。

双端RAM FIFO满队列同拍读写可能撞同地址。此例保留一个空地址，容量2^A−1个未读字＋一个输出寄存器；实际100次满队列持续收发均断言读写地址不同。首次测试台提前一拍放开消费者，导致满占用覆盖条件没达到；保留失败并修测试激励，不改RTL伪造覆盖。统计overflow事件与丢弃beat，不将其直接换算成丢帧/FPS。RAM最终推断及物理频率仍须独立TD。

本机iverilog -V可成功而完整编译仍因后端运行时解析失败，实测默认PATH完整编译返回0xC000007B；将同一工具目录前置PATH后实际编译通过。版本命令不替代完整编译，空stderr也不是成功。保留原调用/返回码，不将运行时准备失败算作算法通过。
