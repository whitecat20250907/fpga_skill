# HCR3 v1 实际行包

这是新的三路 ROI 包格式。双眼是 GRAY8，人脸保留 R/G/B 三个字节，X 不进入压缩。每个包都属于一条实际源 ROI 行；CSI 容器帧不能代替其中的源帧号。默认无量化，delta/offset1 LZ77/store 对送入 codec 的选中字节可逆。

包头 72 字节，小端：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII HCR3 |
| 4 | 1 | 版本 1 |
| 5 | 1 | ROI 0/1/2 |
| 6 | 1 | 通道数：双眼 1，人脸 3 |
| 7 | 1 | 源标志：bit3 可信，bit2..0 帧原子使能掩码 |
| 8 | 4 | 包序号，模 2³² 连续 |
| 12 | 4 | RAW accepted 源帧号 |
| 16 | 4 | 帧原子配置序号 |
| 20 | 8 | 源 SOF 微秒时间 |
| 28 | 2+2 | ROI 原点 x/y |
| 32 | 2+2 | ROI 宽/高 |
| 36 | 2 | ROI 内行号 |
| 38 | 2 | 通道 mode 位：1 为 LZ，0 为 store，unused 为 0 |
| 40 | 24 | 12 个 uint16 实际通道长度；双眼后八项为 0 |
| 64 | 4 | 实际原始行的 CRC32 |
| 68 | 4 | 前 68 字节的 CRC32 |

CRC32 与 Python zlib 一致。通道编号是 `pixel_mod4 * channels + channel`，RGB 的 channel 为 R/G/B。先按每个通道独立做 8bit 差分，再进行 offset1 匹配：FF00 为字面 FF；FF、80|(长度−3) 为复制上一差分值 3..130 次。编码不能省字节时 store 差分数据。

载荷以每通道两字节为一组，依次通道 0..3 或 0..11，再进入下一字节对。只补齐到所有通道**实际编码长度的最大值**的偶数边界，补字节必须为零；补字节不计通道长度，不参与解码。总线包长度为 `72 + ceil(max_length/2)*2*4*channels`，总是 8 字节的倍数。硬件每拍输出 64 位，低字节先发送。载荷字节总数、HCR3 在线包字节、实际物理 CSI 容器字节须分别报告。

CAP/WAIT_ENC/ENC/READY/SEND/FREE 两 bank 所有权控制在 `hci03_row_codec.v`。发送端读完最后一个实际包字前不得释放；无空 bank 时整条新行显式丢弃，计数并保存其源帧号。跨时钟桥每个数据字使用逐字 Gray 退役，另用逐包 Gray 描述符发布完整包；禁止将按行跳变的提交指针直接当作安全 Gray 过域。

数字证据在总工程 `pcie_imx415_bar_contract37_20261010/evidence/hci03_roi_transport_v4`：1423 个正常包和 6 个溢出后保留包，逐字节/元数据/模式/长度/CRC 与独立 Python 规范一致，8406 次逐字节及长度损坏被严格拒绝。源输入按 625000 周期/帧预算运行，对应名义 75MHz 时钟下的 120Hz 容量；该单时钟功能 TB 用 100MHz 仿真时钟，不是 sensor 实测 120fps。独立异步桥用供应商公开功能模型通过 203 包、2476 个 64 位字、三个时钟比和满缓存/复位检查。

`rk/hcr3_frames.py` 将严格解出的行重组成完整 ROI，只发布全部行齐全且源帧/配置/时间/几何一致的图像，保存整图 SHA。实际 RTL 流的九份 RGB/GRAY 整图逐字节通过；缺行、重复、混用配置/时间/原点、未使能及已完成旧帧被拒绝。每路最多两个未完成源帧，溢出与结束时的不完整图像明确计数。整图 SHA 与模型预处理后的 tensor SHA 分别记录。

当前完整生产顶层已接实际 crop/特征/codec/CDC/CSI 和独立 RK DPHY，并保留 DDR/7寸DSI。实际75MHz并发全HD三帧的2112行、6个真实特征、9张整图逐字节通过；自身 native/实际 RK MIPI、当前模型绑定/正例仍待签核，见 README 与 progress_v3。

## HCE3逐测量特征

每个实际眼部结果脉冲形成一个144字节包，低字节先行。每眼独立8整包ERAM槽，写入忙或满时丢整包并保存源FID；不会阻塞测量引擎。三个源（ROI行、左眼、右眼）公平轮转，选中一个后直到last握手才切换。

| 偏移 | 字节数 | 内容 |
|---:|---:|---|
| 0 | 8 | HCE3、version1、eye0/1、uint16包长144 |
| 8 | 4 | 每眼已接受报告序号，模2³² |
| 12 | 4 | 发布丢弃累计数 |
| 16 | 4 | 最近丢弃报告的真实源FID |
| 20 | 4 | 保留0 |
| 24 | 8 | 含当前的received、捕获时sent计数 |
| 32 | 96 | 原HCI02完整24个uint32结果：质量/源FID/配置/时间/原点/尺寸/阈值/面积/五矩/bbox/SAD/亮暗/亮度和平方和/opening面积/组件/分析周期 |
| 128 | 12 | 引擎received、busy skip、deadline累计 |
| 140 | 4 | 前140字节zlib CRC32 |

质量标志仍是权威；有效质心不能直接当已标定注视点。与ROI用真实源FID/配置/时间关联。UART七slot诊断周期与MIPI逐测量报告的速率不同。

## HCS3物理CSI容器

CSI-2 DT0x1e，720×128 YUYV标签，每行1440字节，其内容是协议字节。发送器先在供应商ERAM收齐一整行，再发CSI长包，支持真实PHY ready保持，逐行CRC16/ECC；不在CSI长包内部等待压缩器。载体行允许HCR3/HCE3包跨行与载体帧，源图像必须按源FID重组。

| 偏移 | 字节数 | 内容 |
|---:|---:|---|
| 0 | 8 | HCS3、version1、empty标志bit0、uint16头长32 |
| 8 | 4 | chunk序号，模2³²连续 |
| 12 | 2 | 实际内容字节0..1408，4字节对齐 |
| 14 | 2 | 载体行号0..127 |
| 16 | 4 | 载体帧号，模2³² |
| 20 | 4 | 实际内容zlib CRC32 |
| 24 | 2 | 本行第一个源包起点，4字节对齐；无起点FFFF |
| 26 | 2 | 保留0 |
| 28 | 4 | 前28字节zlib CRC32 |
| 32 | 0..1408 | 实际内容，余下到1440必须全0 |

首次采集只允许根据显式first字段跳过旧包前缀；取得首包后，chunk/载体行帧/各源包序号/first边界/所有CRC连续严格校验，禁止丢坏包后猜magic继续计通过。每路最多两个不完整ROI；缺行不发布图像。完成已开始的128行载体帧后，无输入会等待，不持续发空帧。分别记录选中RAW/RGB/GRAY、编码载荷、行包内容、HCE特征和固定容器全部字节。
