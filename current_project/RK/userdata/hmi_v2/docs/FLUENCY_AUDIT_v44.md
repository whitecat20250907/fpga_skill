# v44 交互误拦截检查

用户要求放宽导致操作中断的防御性条件。本轮更改运行适配器、交互引擎和显示消费者；冻结的模型、轨迹分类算法、FPGA 位流、DMA 协议未改。

| 检查点 | 原行为 | 本轮行为 |
|---|---|---|
| 眼脸模型 | 普通状态仍持续推理，0Hz被抬到1Hz | 单人默认休眠，明确进入眼控/标定才恢复；双人仅保留空间归属需要的人脸链 |
| 手势帧率 | 待机15Hz、未标定10Hz并在推理后等待 | 当前帧处理完即取最新帧，无额外帧率等待 |
| 人脸休眠 | 流不更新被认为人离开 | 主动暂停不构成离开证据 |
| 休眠恢复 | 0.5秒源间隔清空跟踪号 | 主动恢复时强制真实检测，以保留ROI做原空间匹配；不复用旧帧，不伪造新时间 |
| 旧视线 | 滤波残留可能拖慢重新选择 | 恢复眼控时清除视线滤波、旧坐标 |
| 服务故障 | UI、HUD、网页等任一失联全局DEGRADED | 采集/手部故障仍停相应主链；显示/网页只告警；眼控故障退出眼控，手势继续；执行器故障反馈未执行 |
| 界面服务重启 | 重置所有手势准备 | 不再影响准备状态；手部服务重启才清理其旧track |
| 手部短漏检 | 漏一帧清空手势准备 | 同track保留450ms，缺失帧不增加保持时间和帧数 |
| 短暂未分类 | 当作松手，引起重置或重复确认 | 作为暂未识别；不充当明确松手，不二次提交已保持握拳 |
| 重复/乱序消息 | 清空刚才的有效状态 | 忽略该消息，保留仍新鲜的最后有效消息，不增加识别进度 |
| 双手冲突 | 两只手准备状态一起重置 | 暂停冲突提交，保留准备；静态快捷确认限定原操作手 |
| 张开的备用手 | 菜单中被当成取消/冲突手势 | 确认阶段张掌作为准备，不自动退出菜单；标定的明确张掌取消保留 |
| 静态手势边界 | 任意一点越界整只手不可用 | 手掌关键点在5%边界容差内，至少16点在8%容差内；实际大面积出画面仍无效 |
| 左右手分数 | 0.70门槛 | 0.55；已准备的同一确认track可跨短暂左右标签闪动 |
| 静态准备窗口 | 6秒 | 10秒 |
| 快捷确认窗口 | 8秒；HDMI错误显示5秒 | 15秒，HDMI和共享提示一致 |
| 轨迹另一手确认 | 15秒 | 30秒，网页说明一致 |
| 眼控窗口 | 6秒后无论视线状态强退 | 有新鲜有效视线则持续；明确取消/结束退出，连续无效3秒返回手势 |
| 引擎状态有效期 | 显示/执行/网页150ms | 统一350ms，缓解调度抖动误拦截 |
| 网页命令队列 | 350ms | 800ms；保留原命令时间和一次消费 |

现有分类分数与保持规则已经在v40放宽，本轮未继续盲降：静态默认0.60、握拳0.65、拇指0.55、张掌0.50；握拳确认0.35秒且至少3个真实帧。轨迹原分类算法及其 accepted 标志保留。源图像/眼动/手部时间、epoch、动作唯一ID、真实应用回执、坏包校验仍用于数据正确性，不冒充“未识别用户意图”。

## 验证边界

新增回归覆盖界面/网页/眼控故障隔离、执行器故障不伪报成功、HUD重启保留准备、漏检不积累保持时间、置信闪动不重复确认、重复包不计帧、备用张掌不干扰菜单、静态快捷原手确认、左右标签闪动、边缘指尖、有效眼控超过6秒和状态延迟。

板端完整回归与实际服务故障演练见工程根目录 deploy_v44.log、v44_fault_isolation.json。真人识别率和完整新交互流程尚待验证，不把合成观察回归当作真人通过。

## 仍需实现的用户交互改造

“眼控/聚焦进入语义目标选择→原手握拳锁定且眼控休眠→另一手张掌握拳点击”以及“确认手不离开可反复张掌握拳重复上次指令”尚未部署。医学每页实际目标、固定语义区域聚焦、跨游戏/桌面的目标协议需与该状态机一起实现；本轮没有把原鼠标聚焦称作语义目标选择。普通指令仍独立于眼控。
