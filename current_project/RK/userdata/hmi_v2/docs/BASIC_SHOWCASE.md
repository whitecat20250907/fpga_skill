# HDMI 基础功能展示（v80，2026-10-29）

从控制台点击“基础功能展示”，或短按主板 MENU。HDMI 打开独立全屏应用；医学视图状态保留在应用后端；游戏保持进程与状态。2GB 板上仅保留当前医学/基础浏览器窗口，离开时关闭非当前浏览器窗口，避免隐藏 WebGL 和解码图像常驻；不关闭游戏进程。电脑可从控制台“电脑预览”打开同一页面。

## 画面和数字的含义

- 独立高清预览：唯一 C 所有者发布的 1920×1080 ISP 后 RGB 图像。页面使用 RGA 缩到 960×540，再由 RK 编码为网页 JPEG。此 JPEG 仅是显示传输，不是 FPGA 压缩成果。FPS 是高清共享预览发布计数的实际增量。
- 模型识别：640×360 的真实模型输入，加最新 NPU 人脸框、左右手框与手势名称。人脸框使用 x/y/宽/高像素协议，手框使用 21 点范围。框与底图的时间差单独显示；跨硬件代次或超过 500ms 的结果不叠加。没有人在镜头前时不绘制示例框。
- 三个小图：实际 FPGA 640×360、128×128、192×192 平面，来自同一个模型包。128/192 保留硬件补边。三个 FPS 均取模型接收计数，因为三平面同包到达，不是三个独立性能测量。
- 手部 FPS：手部链路处理帧率，包括没有检测到手的帧。人脸 FPS：人脸链路调用计数；没有脸时不表示每帧都执行了 478 点网络。MGaze 仍按原交互在眼控接管/标定时按需启用。
- 页面刷新：显示端图像更新速度，单独统计，不作为相机或 NPU FPS。隐藏页面停止图像请求。固定 Canvas 接收 JPEG 解码结果，每帧 ImageBitmap 绘制后立即 close；同一模型图共用一次解码，避免持续换 img.src 导致浏览器图像缓存堆积。共享缓存让电脑预览和 HDMI 避免重复编码同批图像。
- CPU/NPU0/NPU1 来自系统动态计数。MIPI 是提交速率与协议错误增量，不等同于物理液晶刷新测量。功耗和 FPGA 动态忙碌率没有传感器测量，不推算成已测值。

底部六项要求采用“当前证据”展示。现有 RGB 链路未提供硬件压缩率与吞吐计数，因此硬件压缩明确待实测接入；不能以三个缩图、软件 JPEG 或一个正常页面替代完整基础要求验收。AWB/CNR 位于实际 ISP 路径，但本页没有独立切换各级中间 tap，不将 CPU 滤镜充当 FPGA 结果。

## 主板按键

主板可用的是 RK SARADC 四键；不是八个可随意重映射的 FPGA IO。RESET、PWR、BOOT 保留原硬件作用。

|按键|短按|长按|
|---|---|---|
|MENU|基础展示；暂停后可恢复|2秒暂停交互|
|VOL+|医学展示|释放后仍进入医学|
|VOL−|游戏|释放后仍进入游戏|
|ESC|单人模式|1.2秒双人模式，不再补发单人|

标定、选人、菜单、确认、取消继续由手势或网页完成。HDMI 和网页提示已同步更新，不再提示 VOL− 确认或 ESC 取消。

## 手势映射

新增独立 BASIC 上下文。旧 DESKTOP/GAME/DEMO 映射逐项保留，不覆盖用户自定义。五项入口均可在任何应用映射为系统命令。

基础展示默认轨迹：0 医学、L 游戏、L_rev 基础、M 单人、W 双人。沿用“握拳准备 → 食指画轨迹 → 原手握拳结束 → 另一手确认”的流程。

映射页“填入五入口预设”会填写当前编辑应用的这五项，保留其他项，必须由使用者检查并点“保存映射”后生效。此按钮会替换这五条轨迹原来的绑定，故不会自动对现有应用套用。

## 架构与回退

`console/basic_preview.py` 只读 C 所有者的 memfd，订阅已有模型观测和指标；一个固定图像线程处理所有大块内存复制/缩放/编码，合并并发请求；控制台单独配置 MALLOC_ARENA_MAX=2，限制临时 HTTP 线程的分配 arena。不打开摄像头、DMA/BAR，不重复推理，不把图像放入消息总线。

`system.app_basic` 与医学、游戏共用交互引擎和 Launcher 实际窗口回执。医学与基础页使用同一 Chromium 配置并只保留当前窗口以适配 2GB 内存；以应用 URL 的 WM_CLASS instance 区分窗口，避免共享进程导致选错窗口。

修改按文件 hash 打包；部署保留恢复 tar 与原映射，采集/手部/眼脸主进程 PID 保持不变。`native/display/rga_preview.cpp` 的 RGB888 新接口仅影响高清显示缩放，不改任何模型输入；RGA 不可用时自动回退 PIL，并在页面标明后端。
