# 主程序接入

2026-10-21：开始页也使用同一 UDP 端口与五种事件。只读 `state.phase` 为 `"menu"` 时处于开始页，地图矩形是当前菜单画布；确认开始后关闭菜单端口，再由原生客户端接管。模式和开始按钮都是实际矩形中心目标，没有固定网格。
原生双人模式的状态增加 `hotseat`、`player`、`phase`、`handoff`；`handoff>=0` 时地图被遮住，只提供一个交接候选（kind=8）。下一位需重新唤起、提供新坐标并确认；接管后休眠并清除旧选点。它使用 Freeciv 原生 `/take` 接管不同人类玩家，未创建第二套摄像头或模型，也不等于已验证个人标定/生物身份。
战役增加招募(kind=5)、弓兵支援(kind=6)和本回合原生寻路目标(kind=7)。`army`/`cities` 是只读诊断，适配器接收缓冲已扩大到 32768 字节。

游戏监听 `127.0.0.1:29778/UDP`。不运行摄像头或模型，不接管系统鼠标。

- 坐标：ASCII `gaze 0.52 0.48`，两个值为**游戏地图画布**内归一化坐标，建议 25–60 Hz。标题栏和顶部提示条不属于地图。
- 模型入口优先使用 `gaze2 <source_monotonic_us> 0.52 0.48`，保留源帧的Linux单调时钟微秒，接收端拒绝未来/超过250ms的帧及重复时间戳。该入口接收已经过One Euro的连续坐标，不叠加游戏EMA；旧`gaze`保留为鼠标/脚本兼容入口。
- `gaze_lost`立即清空候选证据并阻止确认。包装器在闭眼、丢脸、退出TRACK或坐标失效时发送，连续失效只发一次；无消息时仍有250ms超时保护。
- 手势事件：`event 123 wake`，事件编号为单调递增整数；重复或过期编号被丢弃。
- 五个事件名：`wake`、`confirm`、`cancel`、`next`、`end`。
- 调试事件 `mouse` 恢复用系统鼠标位置模拟视线；它不是额外游戏快捷键。
- 坐标源年龄超过250ms不能确认。确认只执行一次并退出选点。
- 语义目标选择按真实时间指数衰减（时间常数180ms）累积支持度：支持占比至少0.60、相对第二名领先至少0.12，几何距离优势至少0.08；持续满足120ms且至少3个不同时间戳才就绪。含糊/跳点时可保留旧高亮，但禁止确认，需重新积累稳定证据。模型置信度与选择支持度不是同一个概念。
- 吸附距离按邻近目标间距限制（36～180像素），不会把整屏空白归给唯一目标。以(kind,id,arg)标识目标，列表重排不改变身份；目标集或位置明显变化会清空历史，执行前重新收集并核对当前目标。没有固定8×8网格。
- 候选来自当前部队相邻陆地、可选部队、己方城市和城市操作项，不划全屏网格。
- 维护分支严格拒绝负数/溢出事件编号、未知动作、附加字段和截断报文；非法事件不推进去重序号。非法 gaze 报文使当前样本失效。

在已有 Python 推理循环中引入 `input_bridge.FreecivInput`：调用 `gaze(x,y)` 发送坐标、调用 `action(name)` 发送已有手势识别器产生的离散事件即可。桥接类也有一个可选的 MediaPipe 五类手势映射和持续手势去重示例 `gesture(name, confidence)`；实际手势定义以你的主程序为准。

本维护分支已在 RK3576 实际游戏中验证 UDP 输入、去重、陈旧坐标拒绝和完整战斗。测试坐标不是摄像头模型输出；真实模型、个人标定和原手势仍需联合验证，见 `BOARD_TEST_REPORT.md`。

## 可选屏幕坐标适配（维护分支）

`screen_bridge.FreecivScreenInput` 在原推理回调中调用，不启动任何线程、摄像头、模型或后台服务。`gaze_screen(global_x, global_y, sample_time)` 使用真实 X11 地图画布矩形换算坐标；`sample_time` 必须是该帧的 `time.monotonic()` / Linux `perf_counter()` 时间。超过250ms的源帧、画布外坐标和未知/过期矩形不发送坐标，并使先前活跃选择失效。

矩形由同一个 UDP 输入端口的只读扩展提供：发送 `query <32位小写十六进制随机nonce>`，收到 `state <同一nonce> <JSON>`。JSON 的 `version` 为 1，`map` 为全局屏幕像素 `[left, top, width, height]`；另有回合、休眠状态和当前动态候选用于诊断。新版本增加`gaze_protocol=2`、`selection_ready`、`selection_confidence`，原生客户端另提供`selection_margin`。查询不属于游戏动作。旧版本不提供该扩展时，屏幕适配器停止发送，不能猜测标题栏高度。矩形有效期按请求发出时间计算，最长 250 ms。

RK3576 的可选主程序包装入口（当前app30）：

```sh
<原主程序的python> tools/run_main_with_freeciv.py --app-dir <CURRENT指定应用目录> <原run_gaze.py参数>
```

先通过CURRENT记录的实际所有者正常停止并回收原实例，再用同一环境和原参数启动；回滚时正常退出包装入口并运行原启动命令。包装入口不修改应用文件、标定过程、模型、手势定义或Python环境。它在 `TRACK` 阶段转发连续滤波坐标，绕过原程序可选的区域光标输出，保留原程序其余行为。现有手势事件出口可调用 `app.freeciv_action('wake')` 等五个动作；**此入口不附加示例手势映射**。在取得并验证真实手势出口之前，不能声称已经完成手势联动。

包装入口与原 `gaze.sh` 共用 app 目录上一级的 `gaze.lock`，在导入原模型前拒绝重复实例。正式启用包装入口时，维护者还需登记它的新入口和哈希，再进行完整的主程序生命周期验收；不能将可选适配器测试误报为原默认主程序已经接入。

维护分支新增部分的板端测试状态以 `BOARD_TEST_REPORT.md` 为准。

2026-10-20 用户已明确授权另外部署官方 MediaPipe 手势模块，原手势源码不再是该模块的前置条件。独立环境、复用现有 PCIe RGB、实际采用的五种标签、防连发及启动/回滚见 `GESTURE_RK3576.md`。其动作仍使用本协议，普通视线不下单；默认主程序尚未切换到可选视线包装入口，真人联合测试按用户要求延期。

如果原识别器提供持续姿势状态，使用 `app.freeciv_held_action(name)`（`name` 为原定义已经映射的五个动作，松开时传 `None`）：同一持续动作只发一次，释放后才可再次发送。它不定义任何新手势、置信阈值或识别任务。原识别器已输出离散事件时继续用 `freeciv_action`。

## 2026-10-22 语义预览补充

状态中的 `hover` 是当前新鲜、几何可区分的候选索引，`-1` 表示无可靠候选。它用于蓝色“定位中”显示，不代表可以执行；只有 `selection_ready` 且确认时仍新鲜才允许执行。首次样本可显示候选，但至少三帧独立来源、120 ms 稳定期和既有 250 ms 过期门控仍保留。目标列表用 `(kind,id,arg)` 身份保持分数，数组重排不能更换实际目标。

## 2026-10-23 原生战斗与结束流程

主动作仍为 wake/confirm/cancel/next/end。`next` 在当前本玩家阶段按原生 unit id 循环全部仍有行动力的自有部队，使新招军队和已完成寻路的部队可重新选中。它不补行动力、不自动攻击。

合法 Bombard 支援候选优先于同一个地块中心的移动/近战候选，支持原生规则允许的1–2格；射击不会自动占城。和平移动目标来自原生当前回合可达集合，直接移动还检查ZOC；需要绕行的目标用原生 goto 执行。

结束画面新增 kind=9 的“返回开始页”目标，继续使用唤起、指向、确认，确认后正常关闭本局客户端并由启动器回收服务器。查询增加只读 `game_over`（原生 C_S_OVER）、`owns_enemy_base`、`outcome`（1=夺取敌基地或原生服务器判胜，-1=己基地失守或服务器判负，0=进行中）、`known_enemies` 及 `known_cities`；目标可带 `tile`、`defender`、`defender_hp`、`win_chance`。`owns_enemy_base=false` 不等于没有获胜：人口1的基地可能被原生征服摧毁，此时以服务器终局结果为准。它们不创建新的输入动作，不修改生命、金钱或战争迷雾。完整新版实测状态以 BOARD_TEST_REPORT.md 为准。
